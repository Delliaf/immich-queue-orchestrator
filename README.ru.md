[English](README.md)

Лёгкий контроллер фоновых очередей Immich для домашних серверов с ограниченными CPU и RAM.

> Статус: ранний релиз `0.2.1`. Контракты проверены по Immich `v3.1.0`. Храните актуальную резервную копию и сначала проверьте работу со своей версией Immich.

## Что он делает

- ставит управляемые очереди на паузу сразу после обнаружения новой загрузки;
- сразу запускает в Immich «проверить отсутствующие» при включении автопилота или нажатии «Проверить и обработать»;
- ненадолго показывает найденное количество по каждой очереди, затем обрабатывает их строго по одной;
- прерывает проверку или обработку при новой загрузке, ждёт тишины и полностью проверяет всё заново;
- поддерживает для каждой очереди режимы «управлять», «всегда запущена» и «игнорировать»;
- умеет учитывать число новых файлов в периоде ожидания и периодически проверять отсутствующие даже без загрузок;
- показывает очереди, найденные количества, CPU и все рабочие настройки во встроенной панели;
- записывает состояние и настройки на диск только при фактическом изменении;
- не пишет напрямую в Redis/PostgreSQL и не требует Docker socket.

## Сценарий автопилота

```text
ВКЛЮЧЕНИЕ АВТОПИЛОТА
  -> проверка отсутствующих во всех включённых очередях
  -> после проверки каждой managed-очереди снова пауза и показ количества
  -> последовательная обработка managed-очередей
  -> ОЖИДАНИЕ (managed-очереди на паузе)

новая загрузка в любой момент
  -> немедленная пауза managed-очередей
  -> ожидание заданного периода тишины
  -> новая полная проверка отсутствующих
  -> последовательная обработка
```

Immich выполняет массовую проверку отсутствующих внутри той же очереди, куда добавляет найденные jobs. Поэтому во время инвентаризации оркестратор временно открывает одну очередь, следит за её `QueueAll` job и ставит её на паузу сразу после завершения проверки. Уже активная job не отменяется и может закончиться штатно.

## Простой запуск через Docker Compose

Добавьте сервис под существующим разделом `services:` Immich:

```yaml
  immich-queue-orchestrator:
    container_name: immich_queue_orchestrator
    image: ghcr.io/delliaf/immich-queue-orchestrator:latest
    env_file:
      - .env
    ports:
      - "8005:8005"
    volumes:
      - immich_queue_orchestrator_data:/data
    depends_on:
      - immich-server
    restart: unless-stopped
```

Добавьте named volume в верхнеуровневый раздел:

```yaml
volumes:
  immich_queue_orchestrator_data:
```

Добавьте в существующий `.env` Immich:

```dotenv
ORCHESTRATOR_API_KEY=отдельный_API_ключ_Immich_для_этого_оркестратора
# Необязательно. В закрытой домашней сети можно оставить пустым.
ORCHESTRATOR_ADMIN_PASSWORD=
```

Создайте ключ от учётной записи администратора Immich и дайте только эти разрешения:

- `queue.read`
- `queue.update`
- `server.statistics`
- `job.create`
- `queueJob.read`

Отдельное имя `ORCHESTRATOR_API_KEY` позволяет другим приложениям в том же `.env` использовать свои ключи. Необязательный пароль панели — обычный пароль, не API token; любое непустое значение включает вход, требований к длине и составу нет. Не добавляйте `.env` в Git и не выставляйте панель без пароля в интернет.

Запустите контейнер:

```bash
docker compose up -d immich-queue-orchestrator
```

Откройте `http://<ip-сервера>:8005` и нажмите «Включить автопилот». На другом устройстве `127.0.0.1` указывает на само это устройство, а не сервер. Для ZeroTier используйте `http://<zerotier-ip-сервера>:8005`. Чтобы слушать только ZeroTier, укажите порт `<zerotier-ip-сервера>:8005:8005`.

Готовый фрагмент находится в [`compose.simple.yml`](compose.simple.yml).

Новая установка и обычный restart сами по себе не продолжают очереди: сначала требуется явная команда в панели. После restart автоматически может продолжиться только незавершённый run, которым уже владел оркестратор.

## Панель и настройки

В панели есть вкладки «Обзор», «Очереди», «Автоматизация», «Нагрузка CPU» и «Дополнительно». Рабочие настройки атомарно хранятся в `/data/settings.json`; секреты и начальные сетевые параметры остаются в `.env` или подключённом YAML. Повторное сохранение без изменений и обычный polling не перезаписывают диск.

Порядок по умолчанию:

1. Создание миниатюр
2. Извлечение метаданных
3. Метаданные из Sidecar-файлов
4. Интеллектуальный поиск
5. Поиск дубликатов
6. Обнаружение лиц
7. Распознавание лиц
8. Распознавание текста
9. Перекодирование видео

По умолчанию всеми очередями управляет оркестратор и для каждой включена проверка отсутствующих. Распознавание лиц идёт после обнаружения лиц. В панели настраиваются порядок, режим каждой очереди, проверка отсутствующих, периоды тишины, polling, timeout проверки, адаптивное ожидание, периодическая проверка и CPU guard. Адаптивное ожидание и периодическая проверка по умолчанию выключены.

При каждом выключении автопилота панель спрашивает, что сделать. По умолчанию предлагается оставить managed-очереди на паузе; второй вариант восстанавливает состояния, сохранённые при начале управления.

## Ручной проход

«Проверить и обработать» выполняет такую же инвентаризацию и последовательную обработку, но не включает постоянный автопилот. Если во время ручного прохода начинается загрузка, управляемые очереди сразу ставятся на паузу; после периода тишины полная проверка и проход начинаются заново.

Проверка отсутствующих использует bulk job Immich с `force=false`. Неоднозначный сетевой сбой возле этого неидемпотентного запроса не повторяется молча: панель предлагает принять отправку, повторить её или прервать run.
